# 🃏 مداقش — Mdaqash

لعبة ورق أونلاين **Multiplayer حقيقي** لأربعة لاعبين — بدون أي AI أو Bots.
السيرفر هو المصدر الوحيد للحقيقة (Server-Authoritative): الخلط والتوزيع والرصيد والرهانات والفائز كلها تُحسب على السيرفر.

## 🧱 البنية

```
├── server/src
│   ├── index.ts            # Express (خدمة الواجهة) + Socket.IO
│   ├── socket.ts           # أحداث السوكت (نوايا اللاعبين فقط)
│   ├── shared/             # الأنواع والثوابت المشتركة مع الواجهة
│   ├── game/               # محرك اللعبة — منفصل وقابل للاختبار
│   │   ├── deck.ts         # 16 ورقة (A/K/Q/J × 4) + خلط crypto + توزيع
│   │   ├── dealer.ts       # الترتيب الدائري + يمين الموزع + التدوير
│   │   ├── handEvaluator.ts# قوة اليد: رباعي > ثلاثي > زوجان > ثنائي
│   │   ├── betting.ts      # قواعد المبالغ: مضاعفات 500، حد أدنى 500
│   │   ├── engine.ts       # سير الجولة: مراهنة → حسم → توزيع الجائزة
│   │   ├── sanitize.ts     # تنقية الحالة (أوراقك فقط تصلك)
│   │   └── state.ts        # نموذج الغرفة الداخلي
│   └── rooms/RoomManager.ts# الغرف، المؤقتات، الانقطاع والاستعادة
├── client/                 # React + Vite + Tailwind v4 + Framer Motion + Zustand
├── server/test/            # 45 اختبار وحدة (Vitest)
└── scripts/smoke.ts        # اختبار E2E حقيقي عبر السوكت (44 فحصًا)
```

## 🎮 قواعد اللعبة

- **4 لاعبين حقيقيين** لكل غرفة — تبدأ الجولة تلقائيًا عند اكتمال العدد (عد تنازلي 3…2…1).
- **الموزع** يُحدَّد عشوائيًا أولًا ثم يدوَّر كل جولة، والترتيب دائري: `rightOfDealer = nextPlayer(dealerIndex)`.
- **يمين الموزع مُجبَر على الدخول** بـ 500 على الأقل؛ بقية اللاعبين اختياريون.
- كل المبالغ **من مضاعفات 500** ولا يمكن تجاوز الرصيد (تحقق على السيرفر).
- 16 ورقة تُوزَّع كاملة (4 لكل لاعب). الفائز بأقوى يد بين الداخلين يأخذ الجائزة كاملة، والتعادل التام يقسمها.
- من يصل رصيده إلى **هدف الفوز** (مضاعفات المليون) يفوز باللعبة.
- انقطاع اللاعب يعرض 🔴 مع مهلة؛ عودته تستعيد مقعده وأوراقه، وإن طال انقطاعه في دوره يتصرف السيرفر عنه (المُجبَر يدخل بالحد الأدنى، وغيره ينسحب) حتى لا تتعطل الجولة.

## 🚀 التشغيل محليًا

```bash
npm install
npm run dev        # سيرفر على :3001 + واجهة على :5173 (بروكسي تلقائي)
```

افتح `http://localhost:5173` من 4 متصفحات/أجهزة مختلفة، أنشئ غرفة من الأول وشارك كودها `MDQ-XXXX`.

## 🧪 الاختبارات

```bash
npm test           # 45 اختبار وحدة للمحرك (الأيدي، الرهانات، الأدوار، الجوائز، الخصوصية)
npm run build      # بناء الواجهة + السيرفر
npm run smoke      # E2E: يشغّل سيرفر الإنتاج ويلعب جولتين بأربعة عملاء حقيقيين (44 فحصًا)
```

## ☁️ النشر على Railway

1. ارفع المشروع إلى GitHub.
2. في Railway: **New Project → Deploy from GitHub Repo** واختر المستودع.
3. لا حاجة لأي إعداد — Nixpacks ينفذ تلقائيًا:
   - Build: `npm run build` (يبني الواجهة إلى `client/dist` والسيرفر إلى `dist`)
   - Start: `npm start` (يشغّل `dist/index.js` على منفذ `PORT` الذي توفره المنصة)
4. السيرفر يخدم الواجهة والسوكت من نفس المنفذ — لا حاجة لمتغيرات بيئة.

> ملاحظة: الغرف محفوظة في الذاكرة (مناسبة لنموذج Railway الواحد). عند التوسع أفقيًا بعدة نسخ، انقل حالة الغرف إلى Redis.

## 🔐 Server-Authoritative

العميل يرسل «نوايا» فقط (`game:enter`, `game:fold`…). السيرفر وحده يملك: الخلط، التوزيع، حساب قوة اليد، التحقق من الرهانات، تحديث الأرصدة، وتحديد الفائز. أوراق اللاعب تُرسل لصاحبها فقط، ولا تُكشف أوراق المنسحبين أبدًا.
